## 3. 工单1与2：处理训练身份，完成正式底座

### 3.1 当前先做的保护和审计

确认训练进程是否确实停止；归档停止时 best/last、原run manifest、完整配置、执行源码/patch/必要未跟踪文件、依赖和作者代码版本。检查磁盘足够后采用安全独立副本或受支持的只读快照，不用会随原文件修改的硬链接冒充独立备份。不要在归档里公开密钥或私有凭据。

保留工作区修改，不reset或清除用户文件。可用“已有commit＋完整diff＋必要源码归档＋SHA-256”稳定执行身份；无需为了形式强行提交，但不能把未提交状态写成已提交。项目版本保持0.1.0，未经授权不commit/push/tag。

更新当前状态摘要而非改写历史测试；合成测试数量不是科学进展指标。实际身份需覆盖所执行的代码链，不仅一个入口文件：记录实际import路径，防止旧入口导入新worker。

### 3.2 每个模型选择一条可证实的路线

| 路线 | 条件 | 执行与表述 |
|---|---|---|
| A 原身份恢复 | 原代码/环境可恢复，last状态完整，支持的恢复边界验证通过 | 在原身份继续，数值可复现范围按证据声明 |
| B 新身份续训 | 必须改代码，但状态/迁移可审计且合同允许、获批准 | 新run绑定parent checkpoint、代码diff和累计预算；不得称原run exact resume |
| C 从头新run | 恢复状态缺失或训练语义差异不能接受 | 从批准的源初始化训练，保留历史run |

先调查A，不能仅因新增保存规则就要求全重训，也不能用force忽略hash。若B缺随机状态但仍被批准进行非精确warm-start，必须显式说明缺失、重新初始化的状态及新的轨迹，不能伪造exact资格；其能否作为正式底座由批准的迁移合同决定。

完整恢复需核验模型、optimizer、scheduler、AMP scaler（若用）、step/epoch/phase、原best跟踪、Python/NumPy/Torch CPU/CUDA随机状态，以及支持边界所需的sampler/generator/worker/DDP各rank状态。恢复训练不只是恢复推理权重。[S6] 相同hash和seed不自动保证跨环境或未测试边界逐位一致。[S7]

在独立验证目录，使用真实fit小范围与生产loader对比“连续运行”与“保存→退出进程→新进程恢复”，核验输入顺序/增强、loss、参数、优化器、LR、buffer和随机状态。默认预算可提议每模型总计80次更新以内，但若原合同只支持完整epoch边界，必须选择能覆盖该边界的预算，不能用不覆盖边界的小测试伪称验收。预算在执行前展开批准。

### 3.3 剩余训练与选模

从last续训，不从best回滚。若实际last恰好包含报告的完整epoch，AASIST继续14–80；以实际保存阶段为准，每一个epoch模型均保存下俩，避免scheduler重复step或跳过epoch。这里80轮是履行原锁定预算，不是“科研必须训练80轮”，不另加80轮。

既有best/last可按其原合同验收，缺后来要求的逐epoch文件不自动否定旧run；保存和选模证据不充分时如实阻塞。新不可变保存从真正执行起生效，不能伪造epoch文件。

最终best只按原source_val规则。SSL多个epoch EER=0时，沿用原实现/批准合同中的并列规则（如严格改善保留最早）；若记录不足不能凭2019 eval表现选epoch。新源seed必须采用运行前固定的并列规则。cal0/select/目标结果不得用于源checkpoint选择。

### 3.4 FINALIZED与R4

真实完成预算和选模后才FINALIZED。比较训练模型eval态与导出模型的embedding、head、logits、语义类别映射及最终score。检查首次/重复前向、设备与dtype迁移、mode/buffer、batch/分片、score方向、冻结权重不变。容差按数值模式预先确定。

底座eval/冻结不等于关闭adapter求导；encoder提取与适配更新的梯度边界分别测试。[S8] training_code_hash与export_code_hash分别记录，不能因为使用了兼容导出器就改写原训练身份。

## 4. 工单3：R5源资源与R6最小真实先导

### 4.1 源资源与真实缓存

只接受R4合格模型。每个checkpoint绑定自己的U/M/Fisher/static-R等资源和源阈值，按现有DESIGN允许的角色拟合，不能偷偷用目标样本拟合固定资源。

Frozen的tau0在cal0上按已有规则确定；若原规则欠明确，应在首次使用前固定score方向、阈值算法、并列与边界处理，不依据select/目标效果选择对自己有利的校准规则。cal0不是调参集。

先用固定源小样本做缓存/原路径parity，再提取获准源数据。缓存包含model/snapshot/preprocess/视图/精度/代码等身份，且沿用pickle-free方案。估算源和四个目标的空间与多视图成本，先验证可用磁盘，不一次占满资源。R7前不批量生成目标模型特征/分数作为隐性开发材料。

真实校验K=0、A→B→A、乱序、batch、尾批、分片、逐样本状态隔离、数值坏样本回退。成功返回Frozen分数意味着coverage完整，不意味着适配成功；二者分开统计。

### 4.2 固定源开发条件

已有获批的环境/网格优先；下列为没有冲突时的默认候选，在运行前落成具体配置、版本、随机规则和hash。

| 条件 | 处理 |
|---|---|
| clean | select原始输入 |
| noise20 | 20 dB白噪声；按稳定sample_id/condition/seed派生随机源 |
| band8 | 16k→8k→16k，固定重采样器及版本 |

噪声能量算法、静音输入处理、溢出/削波检查、重采样精度和裁剪补齐顺序必须固定并有单测。所有派生数据留在select，并保留parent/group；不能把派生音频当新的独立测试样本。

开发条件不等于EP内部视图。比如noise20下，最终原视图评分是对收到的加噪输入评分，不能取未加噪版本。方法间共用输入条件、允许的视图、随机实例、裁剪和长度策略。它们只是开发代理条件，不能据此宣称已证明未知生成机制泛化。

### 4.3 必须出现的最小对照

| 比较 | 操作 | 解释目标 |
|---|---|---|
| Frozen | 固定模型，当前输入原视图 | 原检测器基准 |
| View-average，无更新 | 与EP相同的视图集合，固定平均方式，无梯度更新 | 排除只因额外观察获益 |
| 完整EP | 保持原设计 | 总体效果 |
| static R | 允许源数据上拟合的固定变换 | 动态适配是否必要 |
| scalar/subspace/P0/P1 | 复用已有定义和既有候选清单 | 简化校准/结构解释 |
| 去保护项 | 一次去掉一个预定保护模块 | 保护对有害翻转的影响 |
| 相同变量的简单目标 | 已有熵/一致性内部对照，按真实实现标注 | 新目标是否有独立价值 |

View-average必须明确平均概率还是logit、包含哪些视图以及如何转换为合法score，不能查看目标后选择聚合方式。K=0主要是正确性检查，不冒充一种新算法。

未完成作者算法核验的实现只能写内部变体，不能称忠实published baseline。方法选择和底座条件会影响TTA比较，必须固定并披露。[S9]

### 4.4 有限搜索与选择

默认EP网格：K∈{1,3,5}，eta∈{0.3,1,3}×eta_ref，共9个配置；eta_ref读取当前有效配置，打印实际数值，其他参数固定。原17点scalar等已定对照原样保留，它们不属于这9个EP配置，也不能悄悄删除。

选择目标：三个select条件EER等权平均最小。建议先导门槛为每条件coverage=1、无约束违规、数值异常回退≤1%、clean EER相对Frozen退化≤0.5个百分点；这是本次提出的操作预算，不是文献定律，必须在看先导结果前固定。安全不更新与数值异常回退分开，不能混算成“失败”。

并列按预先固定容差处理：优先较少更新步数，再按已确定的候选顺序；不追加目标测试打破并列。保存全部候选，不只保留best。没有可行配置时提交有限诊断，不自动扩大搜索或弱化底座。

每底座在一个预先指定的现有合格源seed上开发；其余source seeds复用选好的方法配置但重新计算各自源资源。实际seed与旧建议不同不需要重命名或重训。同底座不能为不同目标单独选择EP超参数。

可在源select记录明确批准的有限诊断修订，但要记录搜索历史及对开发集过拟合的可能性。源select先导不是独立最终结论，H1–H7编号不重新定义。

## 5. 工单4：完整矩阵、外部接入与R7

### 5.1 底座与随机种子

保留AASIST、SSL-AASIST及既有主次定位。目标每底座3个独立训练seed；已有正式批准列表优先。没有列表时，先登记当前seed，再在17/29/43中按固定顺序取未使用值补齐，运行前锁定并披露。不得根据目标结果选seed。

同一父子run谱系不算两个独立seed。同一底座/seed内所有方法共享完全相同checkpoint。新旧run若recipe或迁移语义不同，应区分并披露，不把实质不同训练条件伪装为仅seed不同。通用SSL预训练语料是否与外部目标有隐含重叠可能无法完全验证，结论应限定为“未参与本项目鉴伪训练和方法开发”，不泛称所有预训练都绝对未接触。

### 5.2 五项published方法与公平性

从原registry读取五项清单及作者论文/固定代码身份；核验目标函数、初始化、更新范围、视图、归一化、优化器、reset及顺序。原生batch/online与逐样本episodic变体分开报告，不偷偷强改算法。

需要更新encoder的方法走真实音频/encoder更新路径，不可用固定缓存冒充；不支持冻结embedding协议则明确该限制。内部熵/MEMO风格实现不自动具备算法parity。

各方法都只用源select选择参数，候选空间及预算提前记录。公平不等于强行给所有算法相同数值学习率，也不等于允许新方法无限搜索而对照不调参。失败、不可用、未移植项保留NOT_RUN/BLOCKED；主论文比较不完整时必须承认，不从矩阵消失。

### 5.3 本轮最终比较结构

1. 各目标独立主表：同一底座/seed的Frozen与EP及预定对照；不把四个目标拼成一个巨大EER。
2. 主机制：完整EP、view-average、static R、scalar/subspace及保护消融，保留原P0/P1分析。
3. 安全：同源阈值下的按类有益/有害翻转与失败回退。
4. 稳健性：底座/seed重复；2021按预定来源、codec/传输条件分解；单类组没有EER时标N/A，不编造指标。
5. 成本：源训练和资源拟合一次性成本，与每条目标端到端推理成本分开。

In-the-Wild与2021 DF承担主要外部问题，2019为已暴露参照，2021 LA为传输变化测试。若论文做多个“显著优于”声明，R7前明确主要比较和多重比较策略；单个95%区间不能当成全表同时显著的保证。

默认不新建额外2019压缩/噪声目标套件，避免当前范围膨胀；已有正式批准的附加条件保留其身份或在R7前明确修订，不能静默删除。WaveFake/CodecFake是否运行在R7前定案。

### 5.4 计划必须绑定的信息

核心目标snapshot与范围、扩展决定、暴露/血缘说明；所有底座/seed/checkpoint和源资源；方法/超参数/源码/作者代码；输入预处理和长度策略、视图随机性；原视图score定义/方向；tau0及可选tau_m；reset范围、数值规则、失败处理；指标实现/官方参考工具、统计分组、比较清单与成本口径；执行矩阵、资源预算和实际入口；独立评分与评价权限；所有工件完整hash。

原角色 `control_test` 不强改为另一个schema枚举。可以在独立计划中绑定其“标准参照用途”，保留当前源snapshot身份。逻辑信息缺字段则开发最小兼容层并补测，不能伪造已存在的配置键。

R7前不根据新目标效果选择模型、方法或补充数据。计划中的UNBOUND必须转成具体值或明确阻塞，不能让null悄悄变默认参数。批准绑定实际字节hash；不要在文档中手写未生成的假hash。

## 6. 工单5：目标评分与独立评价

### 6.1 单样本EP协议

固定源模型/源统计/方法配置 → 读当前无标签音频 → 建立独立初始R及优化器状态 → 固定EP更新 → 对当前输入原视图输出分数 → 丢弃该样本适配状态。

U/M和tau0不在目标全集重拟合，底座不训练；不共享R、优化器动量、梯度或会改变决策的累积统计。batch可并行计算独立样本，不能用batch统计暗中引入适配交互。没有随机更新历史的只读缓存复用不属于跨样本学习。

source数据管理员和最终evaluator可持有标签，评分worker只接收白名单输入；不允许依据dataset_id/攻击标记/label-dependent路径选择参数。检测到越权必须拒绝。针对原生online方法按自己的预定信息访问单列报告，而非改变EP主协议。

### 6.2 失败与封存

沿用原合同数值回退：适配失败有合法Frozen分数则回退并记录；Frozen本身不能评分则阻塞，不补零、不删除、不只报成功样本。固定目标样本计数、唯一性与coverage=1；同时报告适配成功率、安全不更新率和数值回退率。

所有预定目标评分通过coverage/score seal后，独立evaluator一次性关联标签。缺方法/缺数据导致矩阵不完整时，不能假装全部完成；在未看效果前提出明确缩减修订并批准，或保持阻塞。

评分期间出现bug允许在无目标指标反馈下做必要工程排错，必须记录修改与受影响工件重算；不能偷偷修改方法。若已经查看结果，后续更改标明post-hoc/exploratory，不能对同批数据重新包装成原确认性实验。

### 6.3 指标、阈值和统计

| 指标 | 口径 |
|---|---|
| EER | 各目标/seed/方法分别计算，统一算法/方向；百分比与百分点明确 |
| AUROC | 固定正类定义；不临时翻转分数以提高成绩 |
| 固定源阈值错误率 | 真人误拒、伪造漏检分别统计并给分母 |
| 有益/有害翻转 | Frozen错→方法对／Frozen对→方法错，按真假分别报告计数与比例 |
| 回退 | 成功适配、安全不更新、数值失败、Frozen无法评分分别记 |
| min t-DCF | 仅LA等有官方适用ASV资源与协议时补报；DF/ITW不编造ASV成本 |
| 成本 | 冷启动/缓存成本、原视图编码、额外视图、适配、总延迟、GPU峰值、源一次性成本 |

官方2021工具支持按明确条件计算EER和适用的min t-DCF；DF不涉及ASV系统，其主要指标为EER。[S1,S2] 主安全分析用每checkpoint的Frozen tau0比较EP和同分数定义的消融。尺度不同的基线不能被硬套同一数值阈值；如补充部署口径，方法固定后只在cal0按同一预定规则求各自tau_m，再冻结到目标。补充校准不得成为新调参循环，若原合同不允许则先审批。

目标EER阈值扫描仅用于评价，不能回写tau0/tau_m。主表与共享阈值安全表、方法专属源阈值补充表分别命名，避免混淆排序改善与阈值移动。

报告同seed的ΔEER=EER_EP−EER_Frozen，负值为改善，随后报告3seed均值和标准差，不挑best seed。建议用2000次配对分组bootstrap、固定随机seed与95%区间：同一次重采样在各方法和各seed上用相同组索引；先各seed计算差值，再平均，避免把多seed预测当独立音频。区间解释为对当前已训练模型、当前测试抽样的不确定性；训练波动另外报告。

分组优先可靠原录音/视频家族，或与研究外推目标匹配的speaker；R7前绑定各数据的单位，不按区间好看与否选择。混合类别家族保持完整；重采样缺类时不得计算伪EER，记录无效复制率并采用预定规则。映射不全时报告局限，不构造看似完整的speaker/家族信息。不同数据集分开重采样，不把2019/2021关系当独立重复证据。

## 8. 每轮输出与最终交付

每轮AI按五段回报：实际代码变更；实际命令/环境/退出码及失败；真实生成工件/完整hash；未解决阻塞及证据范围；下一阶段真实命令和一条批准模板。

最终至少具备：当前数据与曝光说明、恢复及训练身份、FrozenModelBundle、源资源/先导全候选、外部snapshot/固定范围、方法核验矩阵、R7计划、全量score seals、逐目标逐seed结果、翻转/失败/成本/不确定性分析、H1–H7逐项证据边界。

本轮不是给任意算法的性能承诺。源先导有信号才支持继续投入；正式目标出现退化就报告退化。未知生成机制、传播条件和现实来源是不同维度，不能用单一改善替代全部假设。

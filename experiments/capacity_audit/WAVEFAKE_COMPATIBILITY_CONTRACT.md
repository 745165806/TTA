# WaveFake frozen-feature compatibility contract

Applies only to the fixed **development** assignment produced after `wavefake_audit.json`. It does not change production `load_audio`, source checkpoint, source resource bundle, score direction, view definitions, feature dimension, or any historical cache.

- Local input: embedded mono 22,050-Hz, 16-bit PCM WAV bytes in 131 Parquet partitions. Do not trust repeated `audio.path` basenames as unique file references.
- Selection: deterministic seed-2026 sample of 2,048 sorted complete `audio_id` content groups from the 13,100 audited groups; take `R` plus one of `WF1`…`WF7` per group with generator codes assigned cyclically across the seeded group order. This gives 4,096 selected waveforms and near-equal fake-generator coverage. It is an explicitly fixed subset of the local resource, not the full 104,800 rows. Preserve the exact assignment thereafter.
- Labels: `R→0`, `WF1`…`WF7→1` from the explicit Parquet field, held in a separate supervised-development sidecar. The waveform materializer uses fixed partition and row indices and does not use the label sidecar to select or transform audio. The diagnostic supervised trainer may read these development labels after cache coverage validation.
- Decode: `soundfile` float32 mono from embedded WAV bytes. All audited files are mono; reject any unexpected rate, channel count, nonfinite sample or empty waveform.
- Resampling: SciPy 1.13.0 `scipy.signal.resample_poly`, `up=320`, `down=441`, Kaiser beta 5, constant pad, float32 output. Write new derived mono 16-kHz IEEE-float WAV exclusively (`open('xb')`). Never modify Parquet or source audio. Preserve the full resampled waveform until the unchanged production loader crops/pads to 64,600 samples and applies the existing three safe views.
- Feature extraction: same frozen SSL-AASIST checkpoint and bundle, production worker `workers/baseline_bridge.py`, 3 views × 160 float32, original-view spoof score `z·w+b`, higher means spoof. Existing CPU feature-level adaptation code is untouched. Use GPU for waveform SSL extraction.
- Gate: materialize and extract 32 fixed selected waveforms first; require exact ID coverage, finite 3×160 features, unchanged bundle IDs and 16-kHz derived WAV headers. Only then create the complete 4,096-sample cache with no overwrite. Retain all validation and failure artifacts.
- Study limitation: source contains slight label/generator-related duration offsets even with shared rate/codec; a capacity gap here must not automatically be called causal spoof evidence or final generalization.

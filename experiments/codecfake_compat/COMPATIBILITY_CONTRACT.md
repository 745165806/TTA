# Fixed Codecfake 16-kHz compatibility contract

The existing Codecfake mechanism selection contains 512 **unchanged** official-dev IDs: 222 at 16 kHz, 209 at 24 kHz, 52 at 44.1 kHz, and 29 at 48 kHz. Production `load_audio` requires 16 kHz and is not modified. This experiment adds an explicit input materialization step only for the 290 incompatible waveforms. It is a different input preprocessing condition from the original Codecfake cache attempt and is recorded as such in cache provenance.

Implementation: `soundfile 0.12.1` reads raw waveform samples as float32. If multichannel, take the arithmetic channel mean before resampling, matching production's channel rule; all currently selected files are mono. For source rate `f_s ≠ 16000`, use `scipy 1.13.0` `scipy.signal.resample_poly(audio, up=16000/gcd(16000,f_s), down=f_s/gcd(16000,f_s), window=('kaiser', 5.0), padtype='constant')`, then cast to float32 and write a new mono IEEE-float32 WAV at 16 kHz. No peak or loudness normalization, dithering, random crop, or added silence is performed in the compatibility step. The resampled sample count is determined by the polyphase resampler; subsequently **unchanged** production `load_audio` applies its first-64,600-sample crop or repeat rule. Source files are never opened for writing or overwritten.

For native 16-kHz samples the compatibility resolver returns the original WAV path without resampling, rewriting, or any intermediate audio file. The production `workers/baseline_bridge.py extract` worker receives both native originals and derived 16-kHz WAVs with the same checkpoint, source resources, view definitions, view seed, embedding dimension, class-score direction, and fixed selected sample indices. The worker does not receive a label field or an audit manifest.

The fixed first 32 native 16-kHz IDs undergo independent old-production and compatibility-manifest extraction. Their waveforms, features, and original-view scores must match within `atol=1e-5`; any violation stops the run. The same comparison then covers **all 222** native 16-kHz IDs before any non-16-kHz audio is materialized. The compatibility code never widens the tolerance in response to results. Only after both parity stages pass are 290 waveforms resampled and a complete 512-sample production feature cache generated. The cache must match the fixed selected ID set exactly, have no duplicates or nonfinite values, and contain 3 views of 160-dimensional float32 embeddings. Native samples in the final mixed cache are compared again to their parity cache.

The audit CSV records for every fixed ID its original path/rate, target rate, whether resampling occurred, and the exact library/version and policy. All derived WAVs and feature caches remain inside an exclusive per-run result directory and are not committed. No Codecfake label is opened during materialization, parity, or cache validation. Selected-only labels may be opened only after **all** local-distribution objective scores have completed and passed exact coverage.
